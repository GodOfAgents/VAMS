# V3 producer boundary and remaining qualification

This is an inactive EVM producer prerequisite to the full A-G program. It is not a configured authority, custody adapter, consumer, bridge or deployment. The three production contracts are new instances; no existing V1/V2 contract, schema or initializer is modified.

Shared V3 types/interfaces -> PolicyV3 (concrete V3 timelock and source interface) -> SourceV3 (concrete policy/timelock) is acyclic. Source references, including expected chain ID, use constructor-set storage, so reviewed runtime class hashes remain instance-independent. Source rechecks timelock/policy/adapter code and current profile identities on each read. Runtime hash identity alone cannot establish an approved deployment or constructor provenance; a consumer must also authenticate the selected instances through reviewed governance/deployment records. Policy's expected source hash and source's expected custody hash are deployment inputs, not independent trust anchors.

Policy's one-time source binding verifies source.policy()==address(this) and source.timelock()==governance. Configure stages the complete policy root/version/epoch and profile, calls the source, then stores the returned nonzero digest. Its projection excludes that stored digest to avoid self-reference. Failure rolls back root, counters and the entire profile. Source reports the current state even if the stored digest has become stale; the future consumer must compare current and stored digests and fail closed. Timelock generation zero is legitimate; custody sequence zero is unavailable. The actual custody adapter must independently enforce monotonic authority history across every owner/threshold/module/guard/fallback/recovery route; a synthetic setter fixture proves none of that.

The adapter staticcall receives at most 50,000 gas and copies at most three words. Both successful return size and canonical schema/uint64 words are checked before narrowing. Short, trailing, huge, reverting and gas-exhausting responses reject. This fixed mechanism bound is supported only by local fixtures; an actual adapter must be reviewed and measured within the cap before activation. Unavailable data has no cached, event-only, nonce-only or mock fallback.

The explicit new bytes32 ASCII domains are VAMS:CONSENT-PROFILE:V3, VAMS:AUTHORITY:CONFIG:V3 and VAMS:AUTHORITY:SNAPSHOT:V3, right-padded with zero bytes. SHA-256 is applied to abi.encode(domain, static projection/state); static tuples encode inline without offsets. This deliberately supersedes the earlier design document's keccak256 wording for new V3 traffic only. The independent manual generator and full preimages are retained under heartbeat-authority-golden87 in the workspace, with pinned Linux reproduction and Solidity assertions. Python/Solidity vector agreement is not Rust/Aiken cross-language qualification. Existing V1/V2 encodings are preserved.

Root/version/epoch are committed via the profile projection; the final configuration projection has no independently writable stored digest. Snapshot includes the computed configuration digest. Producer state has no caller-supplied registry identity. A future V3 registry must add its own actual address/runtime identity and independently pin source/policy/route implementations and approved instances. Existing V2 consumers remain V2-specific and must reject V3; no compatibility widening or consumer activation occurs here.

No authentic Safe, root signer, challenge/finality service or operator is appointed by these tests.
