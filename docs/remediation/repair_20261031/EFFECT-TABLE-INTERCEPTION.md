## Defect and bounded repair

Stage F requires the persisted effect, authority state and receipt to agree. The earlier guard verified primary/unique constraints but did not inspect table RLS, user triggers or rewrite rules. Such mechanisms can hide reads or intercept writes despite valid unique indexes. The retained `INTERCEPTION-31-BEFORE` campaign has seven tests and 123 failing subchecks, zero errors/skips: simulated unsafe table states entered the protected transaction body, and the lock-mode expectation failed. This is a controlled-response demonstration of missing checks, not a native trigger exploit or duplicate-effect demonstration.

The shared V3 persistence guard now requires both row-security flags to be disabled, no non-internal triggers (including disabled user triggers), and no rewrite rules on every guarded table. All four catalog results must be actual True booleans; unknown/malformed replies reject. Internal triggers are admitted only for the exact six foreign-key relationships declared by the existing migrations (one provider, one V3 authority, four storage4 authority). Both incoming and outgoing relationships are inspected, including external tables. The guard requires validated/enforced, immediate non-deferrable MATCH SIMPLE / NO ACTION relationships and a non-replica session. Each FK must have exactly the four expected enabled, immediate pg_catalog RI_FKey check/no-action triggers, on the exact relation/event, without arguments, WHEN expressions or column filters. Missing, extra, disabled, renamed/rebound or malformed trigger evidence rejects. The static FK declarations are immutable alongside the existing key declarations. The same inherited guard covers all ten provider/V3-authority/storage4-authority tables and their existing 19 required keys. No cache, automatic schema repair, trigger removal or retry is added.

The table lock changes from ROW SHARE to SHARE UPDATE EXCLUSIVE before schema reads. This conflicts with CREATE TRIGGER's SHARE ROW EXCLUSIVE lock. The guard therefore trades concurrency for a conservative inspected-table boundary: guarded transactions sharing a table serialize, and maintenance/DDL can time out. Existing bounded lock/statement timeouts remain; no automatic retry, role grant or privilege expansion is authorized. Native application-role permissions, contention, lock ordering, migrations and DDL races must be measured before acceptance. In particular, migration methods have earlier catalog/advisory SELECTs; this slice does not prove their snapshot/DDL-race behavior.
