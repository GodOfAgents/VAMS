Abstract
Skills are a natural unit for describing what a language model can do and
how its behavior can be changed. However, existing characterizations rely
on human-written taxonomies, textual descriptions, or manual profiling
pipelines—all external hypotheses about what matters that need not align
with the model’s internal representations. We argue that when the goal
is to intervene on model behavior, skill characterization should bemodel-
native: grounded in the model’s own representations rather than imposed
through external ontologies. We instantiate this view by recovering a com-
pact orthogonal basis from sequence-level activations. The resulting basis
is semantically interpretable but need not correspond to any predefined
human ontology; instead, it captures axes of behavioral variation that the
model itself organizes around. We validate this characterization on reason-
ing post-training, using the recovered basis for both supervised fine-tuning
data selection and inference-time steering. We develop lightweight proxy
interventions to identify which directions are most useful for a given model.
Across Llama3-8B and Qwen2.5-3B, selecting data along those directions
improves Pass@1 by up to 20% on MATH-500 and 41% on AMC, outper-
forming data selection based on human-characterized skills. Because the
basis lives in activation space, the same directions also serve as steering
vectors at inference time, improving Pass@8 by up to 4.8% on MATH-500—
an intervention that human-characterized skills cannot support. We further
validate the characterization on safety alignment, where selecting adversar-
ial training data for model-native skill coverage rather than textual diversity
yields more sample-efficient learning. These results suggest that recovering
skills from the model’s own representations, rather than imposing them
externally, provides a more effective foundation for intervening on model
behavior. Codes are open-sourced1.
1 Introduction
Skills are a natural unit for describing what a language model can do and how its behavior
can be changed. If we could identify the skills a model already expresses—and how those
skills relate to the demands of a task—we could intervene more selectively: selecting training
data by skill, steering behavior along skill directions, or balancing coverage across skills.
Most current characterizations of skills, however, areexternalto the model. They are
expressed as subject taxonomies (Arora & Goyal, 2023; Park et al., 2025), textual skill
descriptions (Didolkar et al., 2025), or prompted summaries of demonstrations (Zhang et al.,
2025). This has been useful for data curation and inference-time guidance (Sun et al., 2025;
He et al., 2025; Zhang et al., 2025). But these characterizations are defined independently
of any particular model. Different models need not organize the same data in the same
way, yet an external taxonomy assigns identical categories regardless of which model is
being considered. When the goal is to intervene on a specific model—selecting its training
data, steering its behavior, or deciding which behaviors deserve broader coverage—the

A model-native skill characterization should satisfy three properties. Like any skill charac-
terization, it should becompositionalbuilding blocks: individual skills combine to describe
complex behaviors, just as basis vectors combine to describe points in a space. Unlike
human-defined skill sets, which struggle with exhaustive enumeration and redundancy,
it should becompact: a small set that covers the space of behavioral variation. And by
definition, it should begroundedin the model’s own representations, so that the recovered
directions reflect how the model itself organizes behavior rather than an externally imposed
ontology. Together, these desiderata point to an orthogonal basis in representation space.
In this paper, we instantiate this view with AUTOSKILL. We represent each sequence
using sequence-level activations and recover a compact orthogonal basis with principal
component analysis (PCA). This is a natural first model-native characterization: it is fully
data-driven, model-dependent, compact, and directly usable for intervention. Each example
receives a score along each recovered direction, enabling ranking and selection, while the
opposing poles of a direction can be summarizedpost hocin natural language for inspection.
Because the basis is recovered in activation space—a space already known to support
causal interventions on model behavior (Park et al., 2023; Zou et al., 2023; Arditi et al.,
2024)—the same characterization can support both supervised fine-tuning data selection
and inference-time steering.
We demonstrate the utility of this characterization of model-native skills in two case studies.
In reasoning post-training, the recovered bases differ across models even when computed
on the same trace pool, showing that the characterization adapts to the model rather than the
dataset alone. For example, symbolic calculus appears in both models’ dominant direction,

• We argue that skill characterization for intervention should be model-native, and formal-

• We instantiate this view with AUTOSKILL, which recover orthoganal basis from sequence-

• We validate the characterization across reasoning and safety: model-native data selection
outperforms human-characterized skill baselines, the same recovered directions serve as
steering vectors, and latent coverage yields more sample-efficient safety tuning.
2 Related Work
Human-Centric Skill Characterization.Arora & Goyal (2023) initiated the formal dis-
cussion of skills in language models, and subsequent work has studied skill composition,
behavior, and scaling in stylized settings (Park et al., 2025; Didolkar et al., 2025). In practical
reasoning systems, skills are more commonly represented through human-designed subject
taxonomies, cognitive subskills, or textual capability descriptions (He et al., 2025; Zhang
et al., 2025). Recent work also attempts to expand these ontologies by exhaustively generat-
ing skill compositions (Zeng et al., 2025; Wang et al., 2025b). These approaches make model
behavior more legible to humans, but they still treat skill characterization primarily as an
external labeling problem. Our focus is different: we ask what kind of skill basis is most
useful when the goal is to intervene on the model itself.
Reasoning Data Selection and Skill Profiling.Selecting reasoning traces for post-training
has become a central problem in open reasoning pipelines. Curated datasets such as s1.1
and LIMO show that a small amount of high-quality reasoning data can be highly effective
(Muennighoff et al., 2025a; Ye et al., 2025), but these collections often rely on delicate manual
choices and do not always transfer beyond the setting for which they were designed (Li
et al., 2025). More structured pipelines use explicit skill profiling (He et al., 2025), reward
models (Zou et al., 2025), or heuristic filters such as difficulty, diversity, and trace length
(Guha et al., 2025). In contrast, AUTOSKILLtreats skill characterization as the first step: it
derives the basis directly from the model’s activations and then uses that basis to score,
rank, and balance examples.
Activation-Space Interpretability and Steering.Our work builds on the linear representa-
tion hypothesis, which posits that high-level concepts are encoded as directions in activation
space (Park et al., 2023). Recent activation-engineering methods, especially Contrastive
Activation Addition, show that adding steering vectors to hidden states can modulate
behaviors such as refusal or honesty (Turner et al., 2023; Rimsky et al., 2024). These methods
are typically supervised: they require the target behavior to be specified in advance in
order to construct contrast pairs. AUTOSKILLinstead discovers candidate directionsbefore
specifying the semantics. In that sense, it uses activation space not only as a medium for
steering, but also as the representation in which skills themselves are characterized.

3 A Representational Approach to Characterizing Model-Native Skills
Desiderata for a model-native skill characterization.What properties should a useful skill
characterization satisfy when the goal is intervention?First, skills should becompositional
building blocks: individual skills combine to describe complex behaviors, just as basis
vectors combine to describe points in a space.Second, the characterization should be
grounded in a space that determines model behavior—not individual predictions, but the
persistent patterns that shape behavior across many predictions.Third, the skill set should
becompact. A persistent challenge for human-defined skills is that exhaustive enumeration
is infeasible, yet different skill descriptions often overlap in ways that are difficult to resolve
and require dedicated deduplication pipelines (Dabas et al., 2025b).
Overview of our key idea.Together, these desiderata point to a concrete formalization:
recover an orthogonal basis from the model’s representation space. A basis satisfies compo-
sitionality by expressing each example as a combination of skill directions. Representation
space operates at an appropriate level of abstraction: directions in representation space
modulate behavior across responses, as recent work on activation steering has shown(Zou
et al., 2023; Arditi et al., 2024). Orthogonality enforces compactness: each direction captures
independent variation, so redundancy cannot arise by construction.
We now describe how AUTOSKILLinstantiates this idea. We first define how a skill basis
is recovered from the model’s activations (Section 3.1), then describe how the resulting
directions are interpreted (Section 3.2), and finally show how the same basis supports
multiple interventions (Section 3.3).

3.3 From Characterization to Intervention
Because the basis is grounded in the model’s own representations, it directly supports
multiple forms of intervention.
SFT Data Selection.Not every direction is equally useful for a given model, so we first
identify which directions are most promising using lightweight proxy interventions. We
consider two proxies: (1) performance after pilot fine-tuning on a small subset (e.g., 1k
examples) associated with each direction, and (2) performance under inference-time steering
toward that direction. Once the most useful direction is identified, we score each example in
the candidate pool by its cosine similarity with that direction and select the highest-scoring
examples for full SFT.
Inference-Time Steering.Each direction can also serve directly as a steering vector. By
adding a scaled direction to the hidden states during inference, we steer generation toward
one pole of the corresponding skill axis. Unlike existing activation steering methods, which
require supervised contrast pairs for a pre-specified target behavior, our directions are
recovered unsupervised — the same basis used for data selection is reused for steering
without additional annotation. However, runtime intervention on hidden states is not
compatible with efficient inference pipelines such as vLLM (Kwon et al., 2023). We observe
that modern architectures such as Llama3 (Grattafiori et al., 2024) leave the bias parameters
at the end of each layer unused. By writing the desired offset into these bias parameters,
we achieve an equivalent intervention without modifying the architecture, retaining full
compatibility with standard inference pipelines.
4 Validating Model-Native Skills
We evaluate the proposed characterization in two case studies. Scenario I asks whether
model-native skill directions provide a useful basis for reasoning post-training—both for
data selection and inference-time steering. Scenario II asks whether the same model-native
view reveals redundancy that surface taxonomies miss in safety data. Together, these exper-
iments test whether grounding skill characterization in the model’s own representations
leads to more effective intervention than relying on externally defined skills.

4.1 Case Study I: Reasoning Post-Training
We use long-context mathematics as a test bed because solution traces are long, heteroge-
neous, and difficult to partition with hand-written labels— a setting where human-defined
skill ontologies are likely to diverge from the model’s internal organization.
Experimental SetupWe conduct SFT with a sequence length of 8k tokens and evaluate
performance across three datasets representing varying difficulty levels:GSM8K:grade-
school math,MATH-500:diverse mathematical reasoning problems, andAMC:high-
difficulty competition problems. Inference is limited to the same 8k-token length. We default
to temperature T= 1.0 and also report results under temperature T= 0.1 for baselines
requiring that setup. Results are parsed and validated using math-verify (Kydlíˇ cek, 2025).
Additional training and evaluation details are provided in Appendix C.1.
Baselines.We benchmark AUTOSKILLagainst a comprehensive suite of baseline data selec-
tion methodologies, ranging from curated open-source datasets to advanced reward models
and heuristic filtering.Curated Datasets:We evaluate against prevailing datasets such
as s1.1 (Muennighoff et al., 2025b) and LIMO (Ye et al., 2025). For s1.1, we independently
evaluate reasoning traces generated by Gemini and DeepSeek as two baselines. Further, we
compare againstSkill-Targeted Adaptive Training (STAT)(He et al., 2025), which performs

4.1.1 SFT Data Selection
For data selection, we source training examples from llama-nemotron-sft/math dataset.
From a pool of 50k examples, we compute the top Principal Component (PC) directions
of the activations, each corresponding to two distinct skills (PC+/PC-). For a specific PC
direction k, we rank the 50k examples by their cosine similarity to the direction vector wk
and select the top 25k (Positive Steering, PC+) and bottom 25k (Negative Steering, PC-) to
form targeted datasets. A random subsample of 25k examples serves asBaseline SFTcontrol.

4.2 Case Study II: Safety
Alignment Under Budget
Constraints
This setting tests a different consequence of the model-native view. If skill characterization
is grounded in the model’s representations, then textually diverse attacks that induce similar
activations may be redundant—even when surface taxonomies treat them as distinct. We
study adversarial data selection under tight budgets, where redundant selections are most
costly. Existing work on adversarial skills (Liu et al., 2024; Doumbouya et al., 2024; Wang
et al., 2025a; Dabas et al., 2025b) largely relies on text-level categories such as role-play,
indirection, or obfuscation. Our claim is that effective safety tuning requires coverage of
model-native skills in activation space, not coverage across surface-level attack categories.

5 Conclusions
We argued that skill characterization for intervention should be model-native. Human-
defined skills remain useful interfaces for people, but when the goal is to select data,
steer behavior, or balance coverage, the relevant basis should come from the model’s
internal representations. AUTOSKILLinstantiates this view with a simple activation-space
decomposition: PCA over sequence-level activations yields compact, contrastive directions
that can be interpreted post hoc and reused for intervention. Across reasoning and safety, the
resulting skill axes are semantically coherent, predictive of downstream training outcomes,
effective for SFT data selection, and directly usable for inference-time steering and budgeted
robustness tuning. Taken together, these results suggest that model-native skills are not
merely descriptive—they provide an actionable basis for understanding and changing
model behavior.
Limitations and Future Work.Our results should be read as evidence that PCA is a
strong first model-native basis, not that linear directions exhaust the space of skills. First,
PCA may miss non-linear or polysemantic structure; richer decompositions such as sparse
autoencoders are a natural next step. Second, the semantics of a discovered axis are post hoc
and sometimes coarse even when the axis is intervention-ready. Third, we evaluated the
framework on mathematical reasoning and safety; extending the same analysis to domains
with subjective or open-ended success criteria remains important future work.

A Extended Related Works
Post-Training for ReasoningThe standard recipe for reasoning models involves SFT
on Chain-of-Thought (CoT) data followed by Reinforcement Learning (RL) or rejection
sampling (Lambert et al., 2024; Guo et al., 2025). As reasoning trajectories grow in length
and complexity, the quality of SFT data becomes paramount. Recent efforts in “Super-
Alignment” and distillation from larger reasoning models (e.g., DeepSeek-R1) focus on
filtering data based on difficulty or perplexity (Liu et al., 2025). SFT data is usually selected
to maximize evaluation performance after SFT (Li et al., 2025; Ye et al., 2025), and the best-
performing SFT models are believed to also yield stronger performance after subsequent
RL. Significant research effort is now focused on more sophisticated selection and curation
strategies for SFT data (Kang et al., 2025). Techniques range from filtering for complexity
and diversity to generating synthetic data that covers a wider range of reasoning structures
(Rastogi et al., 2025; Yuan et al., 2025; Ye et al., 2025; Abdin et al., 2024). Some methods
propose selecting data points based on their difficulty and influence, aiming to find a subset
of examples that provides the strongest learning signal (Muennighoff et al., 2025a).

B.1 Spectral Analysis for PCA
Having extracted the sequence-level representations, we aim to analyze the geometric
structure of A to quantify the diversity and redundancy within the sample space. We
apply Principal Component Analysis (PCA) to A. While PCA is conventionally used
for dimensionality reduction, our objective is to analyze the distribution of thesamples
themselves via the singular value spectrum. We perform a Singular Value Decomposition
(SVD) on the centered data matrix:A=UΣW ⊤, where Σ=diag(σ 1, σ2, . . ., σm) contains the
singular values in descending order, with m=min(n , D). We define the relative variance
explained by the k-th component as: ηk = σ2
k
∑r σ2r
. By analyzing the spectrum of singular
values, we assess theeffective rankof the representation matrix. This reveals the intrinsic
dimensionality of the dataset within the model’s activation space: A flatter spectrum implies
that the activations are diverse and have a higher intrinsic rank (High Intrinsic Dimensionality).
This suggests that samples in A possess rich semantic features not easily compressed into a
small number of latent directions. Conversely, a rapidly decaying spectrum suggests that
A exhibits low-rank characteristics (Low-Rank Compression). In this regime, the activations
of the examples are collapsed into a few dominant directions that span the majority of the
information space, indicating high redundancy.
Empirically, reasoning examples are shown to be highly specialized, where the top 5/10
principal directions cover 90%+ variances. This suggests a strong concentration of reasoning
primitives and highlights the prominence of these latent modes.
B.2 Fully Compatible Steering via Model Editing
The approach is training-free, but inference-time interventions may require modifications to
the inference pipeline. We propose a novel model editing approach to bake the intended
steering directly into model weights, circumventing implementation-side complications.
With the target steering vector, we directly add its values to the bias parameters at the end
of each layer in the model, achieving an equivalent offset on the model’s hidden states
without needing explicit intervention during inference. The edited model has the exact same
architecture as the original model, retaining full compatibility with its original inference
pipeline such as vLLM.

I Safety Training Dataset Construction
We construct safety training datasets with a fixed benign-to-harmful ratio of2:1across all
experimental settings to ensure comparability across adversarial budgets.
Adversarial and harmful samples.Adversarial samples are selected according to the
budgets described in Section 4.2, using either AUTOSKILL-based latent-space selection or
random sampling from the full set of jailbreak prompts.
Benign samples.Benign samples are randomly sampled from the vanilla benign queries
provided by the PKU-SafeRLHF dataset (Ji et al., 2024).
Target responses and refusal templates.For all harmful queries, the target response is a
refusal. To avoid overfitting to any single refusal pattern, we uniformly sample the target
response from a fixed set of 20 refusal templates shown below. This encourages stylistic
diversity in refusals while preserving semantic consistency.
• “I can’t assist with that.”
• “I’m unable to help with this.”
• “I must decline that request.”
• “I can’t comply with that.”
• “I’m not able to do that.”
• “I’m sorry, but I’m not permitted to handle that type of request.”
• “That’s something I can’t produce or participate in.”

J Safety Evaluation Datasets
Robustness is evaluated on two 2,000-query adversarial test sets from prior works (Jiang
et al., 2024; Dabas et al., 2025b).
For the skill-composed evaluation dataset, each query is constructed by composing multiple
named adversarial skill primitivesdrawn from a curated skill dictionary. These primitives
capture common jailbreak tactics (e.g., role-play framing, mediated attribution, obfuscation,
output-format enforcement, and example-based noncompliance seeding) and are systemat-
ically combined across composition depths ranging from 2 to 5 skills and multiple harm
categories.
The dataset emphasizescompositional diversityrather than prompt paraphrasing: even when
base harmful intents are similar, adversarial prompts differ substantially in structure and
interaction style, ensuring broad coverage of the adversarial skill space and reducing reliance
on fixed templates or shallow lexical cues.
